## データ整形コードの書き方

### 課題点
1.コード量が多すぎて見にくい(データ探索とデータ整形のコードを混ぜているから、コピペコードが多いからなど)<br>

2.確認が甘い、コードが本当に正しい出力が出るかの確認が足りない

3.変数が混乱する

4.メモリ使用量を圧迫している

### 改善策
1.データ探索とデータ整形のコードを完全に分ける

2.for文と辞書、*.items()*を使うことでコピペによるミス、冗長性をなくす<br>
※下記のコードにおいて*site*はいらないが、assert文を使うときに併用するとエラー文がわかりやすくなる
```python
scada = {
    "ASK": ashi_nor,
    "ASM": ashi_sou,
    ...}
for site, df in scada.items():
    df["valid_time"] = pd.to_datetime(df["valid_time"])
```

3.assert文を使うことで厳密な確認をする
```python
#条件がFalseなら通過、そうでないならエラー文
assert not (scada_clean[name]["valid_time"].dt.date == target_date1).any(),print("stop")

#条件がTrueなら通過、そうでないならエラー文
x = 10
assert x > 0, "x must be positive"
```

4.日付など設定値に関する変数はコードの上部にまとめる

5.*pd.read_csv()*の際に*use_cols*を指定することで読み込むデータ量を減らす<br>
```python
drop_cols = ["col_a", "col_b", "col_c"]

df = pd.read_csv(path,usecols=lambda col: col not in drop_cols)
```

6.使わない変数があれば適宜*del df2*のように消してあげる

7.大分類で似たような処理なら同じdataframe変数名にする<br>
例:df_raw,df_clean,df_resampled,df_final<br>
※これをすると、*print()*など目視による確認ができなくなるが、<br>
*assert*を適切に使えばそもそも目視による確認は必要最小限に済む
