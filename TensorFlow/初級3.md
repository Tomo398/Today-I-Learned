### batch_sizeの指定方法
基本的に三通りある。

1.fit()の際に引数として指定する

2.tf.data.Dataset()として、データの読み込みからバッチサイズの指定まで行う

3.pd.read_csv()をした後、tf.data.Dataset()でバッチサイズの指定を行う

1は非常に簡易的であり、実装が楽である。しかし、学習速度が遅くなったり、学習データが巨大であった場合、メモリ容量が足りなくなり、読み込めないという状況が発生するリスクがある

3は学習速度の面は改善されるが、以前としてメモリ容量の問題は解決されない

2は両方の問題を解決するが、やや実装に慣れが必要という問題がある

目指すべき姿は2であるため、2の実装例を紹介する

コード例

file_path = 'data_A.csv'

直接 Dataset 型として読み込む
batch_size や label_name（正解ラベルの列名）を指定できる
```
A = tf.data.experimental.make_csv_dataset(
    file_path,
    batch_size=32,      # 32個ずつの塊にする(まだ訓練用とテスト用と分割できていないなら1にして分割できた後サイズを指定する)
    label_name='target', # 正解データとなる列の名前
    num_epochs=None,        # データを何周するか（1周）
    ignore_errors=True   # 読み込みエラーを無視するか(開発中はFalseがよい)
)
```
※num_epochsはDatasetオブジェクトから、何周分のデータを取り出せるかという意味あい、仮に1なら1周で終わり、Noneなら無限に取り出せる。現環境では、Noneを指定する方法が一般的であり、その代わり、fit()の際の引数としてsteps_per_epochを指定してあげる必要がある。(データ数/バッチサイズ)

※batch_size注意、
train_ds = full_ds.take(train_size).batch(32) # 8000件取る
val_ds = full_ds.skip(train_size).batch(32)  # 8000件飛ばして残り取る
のように、訓練データとテストデータが分割できていないときはこのようにバッチサイズを指定することが望ましい

※.take(n)と.skip(n)について
これらはdataset型のデータから抽出するメゾットで、.take(n)の場合nバッチ分のデータを抽出し、.skip(n)ならnバッチ分無視し、それ以外のバッチを持ってくる

今回はcsvだったため、**tf.data.experimental.make_csv_dataset**だったが、画像データの場合は**tf.keras.utils.image_dataset_from_directory**、numpy配列やリストをDataset化する際は**tf.data.Dataset.from_tensor_slices**を用いる

### df.element_spec

### tf.strings.lower(input_data) 
テキストを大文字から小文字に変換する

### tf.strings.regex_replace(lowercase, '<br />', ' ')
HTMLの改行タグを空白に変換する

実質的にやっていることはre.subやreplaceのなどと同じだが、cpu上で動いてしまうため、大量のデータを一貫してGPU上で行うためにはtf.strings.regex_replace(変数名(tensor),文字のパターン(正規表現),rewrite(書き換える文字列)) を使う必要がある

　
### layers.TextVectorization()
生の文字列を、Embedding レイヤーまたは Dense レイヤーで読み取ることができるエンコードされた表現に変換する
主にやっていることは標準化(テキストの掃除)、分割(文章を文字、単語単位で区切る)、数値化(切り分けた単語を、語彙名簿（Vocabulary）に基づいて数字（ID）に置き換える)

引数は以下の通り

#### max_tokens
語彙の最大数。頻出する上位何単語を覚えるかを指定。10000単語程度が一般的。

#### standardize
テキストの掃除方法、自作関数か'lower_and_strip_punctuation'を指定する

#### split
単語をどう分けるか、'whitespace' (空白で分ける)

#### output_mode
出力形式。整数リストにするか、回数カウントにするか。int,multi_hot,countなど

intだとそもそも背番号(辞書)的に単語に一つ一つ番号が割り振られる。LSTMやBertで用いられる
multi_hotだと巨大なリストが生成され、順番を加味しない、単語のあるなしのみの要素ができる
countだと単純にその単語の頻度(重要度)を見る

#### output_sequence_length
(説明変数として)出力する数字リストの長さを指定。指定したものより長いと切り捨て、短いと0でfillする

そもそも、DNNは入力データサイズがバラバラだと計算できないという性質がある。実際、レビューなら短文もあれば長文もある。そこで、むりやり長さを揃えるのがこの引数の役割となる

#### ngrams
「2単語ずつのセット」なども考慮するか。


※詳細はデータの読み込みと前処理を参照

### .get_vocabulary()
各整数が対応するトークン（文字列）を検索できる

例
vectorize_layer.get_vocabulary()[1287]

### .cache()
一度読み込んだデータをメモリ（RAMまたは速いディスク）に保存しておくメゾット。通常だとdataを読み込み、レイヤで処理してベクトル化してモデルに渡すという行為をエポックごとに繰り返してしまう。そうならないように、1エポック目の完成品をメモリに保存させるようにしている

### AUTOTUNE = tf.data.AUTOTUNE
### .prefetch(buffer_size=AUTOTUNE)
GPUで学習している間、CPUを使い次に学習するデータの準備を行う
何が最適かというのは**tf.data.AUTOTUNE**でtfに任せることができる

### layers.Embedding(input_dim,output_dim)
input_dimで語彙数(辞書に登録されている単語の総数)、output_dimで埋め込み次元(1つの単語をいくつの次元(特徴量)で表現するか)を指定する

word2veqなどの既存空間を利用したり、利用した上で更に学習したり、一からベクトル空間を作成したりするという手段がある。(2つ目の方法は実質的に転移学習である)

仮に一から(正しい)ベクトル空間を作成する場合は相当なデータ数を必要とするため、既存ベクトル空間を利用する手法が好ましい

※ベクトル空間の作成と、損失の最小化が同時に行われているように思われるが、やっていることは損失の最小化のみで、結果的に最適なベクトル空間が行われているだけである。

### layers.GlobalAveragePooling1D()
通常のAveragePoolingと異なり、Global1Dは全体を平均し、**一つ**の値を出すため、カーネルサイズは指定する必要はない

※自然言語処理だと(バッチサイズ, 単語数, 特徴量数)というshapeになる

### tfk.Sequential([vectorize_layer,model,layers.Activatio('sigmoid')])
前までは、文字列を手動で数値に変換してから、モデルに学習させていたが、本番環境でそれをユーザー側がいちいちやるのは現実的ではない
