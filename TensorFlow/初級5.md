### オーバーフィットとアンダーフィット  

###  tf.data.experimental.CsvDataset()
csvをdataset型として読み込むための関数。make_csv_datasetでは綺麗なcsvしか対処できない、よって、ヘッダーのスキップ、utf以外のエンコードの対処等がしたい場合は、pandasを使うかこの関数を使うほかない

主要引数一覧

**filenames**
読み込むファイルのパス

**record_defaults**
各列の型とデフォルト値のリスト。列の数だけ指定が必要。

例1:仮に読み込む列が3つだった場合(この場合空欄があるとエラーを吐く)
record_defaults=[tf.string, tf.int32, tf.float32]

例2:仮に読み込む列が無数にあったとき 
record_defaults = [tf.foat32] * (FEATURES + 1)

例3:読む込む列が無数にあり、かつ欠損値を0で埋めて欲しいとき
record_defaults = [0.0] * (FEATURES + 1)

例4:値がない場所をNaNで埋めて欲しいとき
record_defaults = [np.nan] * (FEATURES + 1)

**compression_type**
圧縮形式(GZIP)

**header**
Trueにすると各ファイルの最初の1行をスキップできる

**na_value**
csvにnaやnullと書かれているとき、それらをnap.nanに置き換えてくれる

※naをそのまま渡すと深層学習ではエラーを吐いてしまうので、.map()を使って平均値や0に補完する必要がある

※この関数ではbatch_sizeを指定できないが.batch()で結局後から指定できる、また正解ラベルの指定もできないが、後で指定する（詳細後述）

```def pack_row(*row):
       label = row[0]
       features = tf.stack(row[1:],1)
    return features, label
```
ここで正解ラベルの列と特徴量の列を別々にまとめる関数を作成する、
正解ラベルを指定する引数のない関数のときはこれが必要となり、.map()で適用させてあげる

### .batch()
効果については言うまでもない。問題はその引数、大きさだ。

バッチサイズは機械学習の分野の慣習1として2のn乗の値が使われることが多く、32, 64, 128, 256, 512, 1024, 2048辺りがよく使われる数値らしい
**データセットの件数が数百件程度であれば32, 64をまずは試してみて、数万件程度であれば1024, 2048をまずは試して見るのが良い**

また、データサイズに対してバッチサイズが綺麗に分けられることはなく、その場合ミニバッチとして活用されることが多い(無視もできる)

### .unbatch()
一度batch()したものをほどく行為、学習のためではなく、データ整形の(効率化の、ラベル仕分けの)ためにやむなくバッチ化したとき に使われる

### .repeat()
データを無限供給するためのメゾット、基本は空欄でよい

### .shuffle()
データをシャッフルさせる、引数は主に*buffer_size*,*seed*である
*buffer_size*はデータ数と同じサイズにすれば完全なシャフルになるため、データが巨大でなければ**データ数と同じでいいか**

### tf.keras.optimizers.schedules.InverseTimeDecay()
学習率をエポック(ステップ)数とともに徐々に下げる関数、通常は過学習を抑えるために使う、引数は以下の通り

#### initial_learning_rate
スタート時の学習率

#### decay_steps
減衰の基準となるステップ数、ステップ数自体はデータ数/バッチサイズで導ける

#### decay_rate
減衰の勢い、この値が大きいほど学習率が急激に下がる

#### staircase
グラフの形、Falseなら滑らかに減少し、Trueだと階段状に減少する

### tf.keras.callbacks.EarlyStopping()
普通は、定義し変数に入れた後、fit()の中にcallbacks=[early_stopping]として組み込む
引数は**monitor**(監視する指標（検証用データの誤差）),**patience**(改善が見られなくなってから何エポック様子を見るか（待つか）)**restore_best_weights**(学習終了時に、一番精度が良かった時点の重みに戻すか)である

### input_shapeについて
```
model = tf.keras.Sequential([
    layers.Input(shape=(28,)), # 1. まず「入り口」だけを定義する
    layers.Dense(16, activation='relu'), # 2. input_shape は消す
```
input_shapeは既に推奨されず、レイヤーとしてlayers.Input(shape=)が求められる

※Tensorflowの畳み込み層では、*NHWC*の順序が求められる。(pytorchはNCHW)

※NはBatch size、HはHeight、WはWidth、CはChannel(意味あいは奥行だが、画像データは色(白黒なら1,カラーなら3,透明+カラーなら4となる))を指す

### layers.Permute()
次元の順序を入れ替える、仮に、((CHW))を((HWC))に変えたいなら、*layers.Permute(2, 3, 1)*を使う
これはtfk.Sequentialの中で使う

### kernel_regularizer=regularizers.l2(0.001)
正則化項、基本layers.Dense()の引数として入れる,勿論l1もある
また、fitを使う場合は気にしなくていいが、tf.GradientTape等を使ってカスタムループを作る場合は、正則化項が学習率に影響されないようにする必要があるため*AdamW*などを使った方がいい
